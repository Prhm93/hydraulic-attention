## 1 — What the project is

A transformer for flood forecasting whose attention bias is set by **hydraulic
travel time (τ), recomputed from the current water state at every timestep**,
instead of by feature similarity or a fixed distance. A second term is a
**terrain barrier gate (Φ = −α·τ + β·S)** that blocks attention between patches
separated by high ground.

- **Narrow novelty claim:** state-dependent travel-time weighting. That is all.
- **The ablation table IS the paper.** Variants 1 / 4a / 4b isolate whether each
  term earns its place.
- **Goal:** a buildable, publishable paper in ~1 month of GPU access.
- **Repo:** https://github.com/Prhm93/hydraulic-attention (private).
- **Hardware:** A100 80GB PCIe, ~42 GB MIG slice, 59 GB system RAM.
  `nvidia-smi` is permission-blocked on the slice — use
  `python -c "import torch; f,t=torch.cuda.mem_get_info(); print(f/1e9, t/1e9)"`.

### Novelty verdict [verified by literature search, 23 Aug]

The narrow claim survives. No published or preprint work was found that
recomputes an attention bias each timestep from an evolving physical state via a
propagation speed.

Component-by-component:

| Component | Novel? |
|---|---|
| Additive pre-softmax bias slot | **No.** ALiBi / T5 / AlphaFold pair bias. Several physics-informed transformers already put PDE terms there. Do not claim it. |
| τ from shallow-water celerity | **Yes**, inside attention. |
| **Per-timestep recomputation from state** | **Yes — this is the actual novelty.** Frame the whole paper around it. |
| Terrain barrier gate | **Weakly.** Elevation gating exists in flood ML (EvaNet, Hidden Markov Tree terrain-aware mapping). |

**Closest work to cite and distinguish:**
- **FieldFormer** (arXiv 2510.03589) — learnable velocity-scaled distance metric,
  but trained-static, and it is sparse-sensor reconstruction not rollout.
- **PDFormer** (AAAI 2023, 37(4):4365–4373, arXiv 2301.07945) — traffic
  propagation delay, but two *precomputed static* masks.
- **Continuous-Time Attention** (EMNLP 2025, arXiv 2505.20666) — PDE over a
  pseudo-time axis; wave speed is a design constant, not read from a state.
- **Transolver Physics-Attention** (ICML 2024, arXiv 2402.02366) — feature
  similarity slices, exactly what this contrasts against.
- **SWE-GNN** (Bentivoglio et al., HESS 27:4227–4249, 2023) — CFL sets layer
  count, precomputed per rollout.
- **Tesán et al.** (CMAME 449:118476, 2026 / arXiv 2507.08861) — CFL for GNN hop
  count. Nearest use of the same intuition; also the source of the obvious
  reviewer question "why not do this in a GNN?".
- One unverified item to check by hand: arXiv 2605.25115 "Courant" — PDF was not
  machine-readable.

**Venue guidance.** Not ICLR/ICML/NeurIPS main track at one mechanism + one
dataset. Realistic: NeurIPS ML4PS or Climate Change AI workshop now; Geoscientific
Model Development / Environmental Modelling & Software / Water Resources Research
if state-dependence beats a static-celerity control **and** helps out-of-domain;
Journal of Hydrology or Environmental Data Science if in-distribution only. **A
clean null is publishable at a workshop** provided the controls are rigorous.

**Expected reviewer attacks, in order:**
1. Ablate-or-it-didn't-happen — especially the **missing static-celerity control**.
2. Why an attention bias rather than a GNN/CFL layer schedule.
3. Is any gain physics or just extra capacity — report learned α/β/ε.
4. Missing baselines: SWE-GNN specifically, plus FloodSformer or SwinFlood and a
   plain ViT+ALiBi.
5. One dataset caps the venue.

### Why only Australia + UK are usable
30 m depth exists ONLY for Australia and UK — that is the dataset's own design
(high-fidelity 30/60 m vs low-fidelity 480 m). **480 m kills the mechanism**: one
480 m cell already exceeds the ~470 m shallow-water reach per 300 s step, so
patching collapses every reach into one patch and τ has nothing to vary over.
Pakistan also used downsampled-then-simulated with a river-inflow boundary
condition rather than rainfall — a different generating process.

## 3 — Design decisions, settled by measurement

| Decision | Value | Why (measured) |
|---|---|---|
| Prediction horizon | **7,200 s (24 frames)** | 300 s abandoned: velocity persistence hit 97.6% skill. At 7,200 s trivial skill drops to ~54–61%. |
| Crop / patch | **512×512 crop, central 256 scored, 32×32 patches → 256 tokens** | Covers 15.4 km; discrimination ratio 8.66 shallow-vs-deep reach. |
| Crops per frame | **9** (stride 256 on 1073) | |
| Training examples | **20,304** (benchmark, days 1–8) / **22,464** (stress, 10 days minus day 7) | [verified in run headers] |
| Domain scored | **51.2%** (central tiles, 128–896) | Outer ~49-cell band never scored; least trustworthy at free-outflow boundary. Accept + document. |
| Spatial split | **DROPPED** | 1073 cols can't hold two leak-free 512 regions (needs 1536). `splits.py` deleted. |
| Same-region test | **Temporal** | days 1–8 train / 9–10 test (benchmark), + day-7 holdout (stress). |
| Cross-region test | **Whole UK domain** 170×275, fed as one piece | 512 crop doesn't fit in 170; must also evaluate Australia whole-domain to isolate shape change from region change. |
| Normalisation | **Fixed constants, never per-region** | H_SCALE=1.0, DH_SCALE=0.05, BED_SCALE=10.0, MANNING_SCALE=0.1 [chosen]. |
| Scale invariance | **NOT a clean claim** | 30↔60 m Courant ratios 0.834–0.922. Usable-with-bias-stated only. |

### Known simplifications to DECLARE in the paper
- `travel.py` averages endpoint celerity, not path integration — two deep patches
  split by dry ground look connected.
- One Φ shared across all heads and all layers (relative positions ARE per-head;
  α/β global by choice, so variant 4 can't win via positional capacity).
- Solver omits convective acceleration — any Froude>1 rule targets behaviour the
  data can't represent.
- **vs SWE-GNN:** they set layer count from timestep via CFL, precomputed; ours
  recomputes τ from current depth every step. State plainly or it reads as
  reinvention. Locality prior is *inspired by* CFL, NEVER a stability guarantee.
- Only 51.2% of the domain is scored.
- Land cover codes 9/10 → rangeland.

## 5 — The model (`hat/model.py`), 7 classes

Total **3,654,052 params** at in_channels=4, dim=192, depth=6, 4 heads.

1. **PatchEmbed** — Conv2d stride=kernel=32, (B,C,512,512)→(B,256,dim).
   dim=192 [NEED FROM ME] — no measured reason.
2. **BiasedAttention** — single-head, additive bias slot before softmax.
3. **MultiHeadBiasedAttention** — 4 heads, shared bias, head_dim=48.
4. **Block** — attn + per-token MLP (ratio 4), residual + pre-norm. 444,864 params.
5. **RelPosMLP** — relative position bias from a tiny MLP on (dr,dc), per head,
   228 params. **Replaced RelPosBias**, which had a fatal bug: a fixed 16×16 table
   returned 256×256 for ANY grid, silently breaking the cross-region claim.
   **The plain baseline uses this same scheme, or the comparison is unfair.**
6. **HydraulicTransformer** — patch embed → 6 blocks → predict Δh per patch.
   Grid read from input, so any size works.
7. **PhysicsBias** — Φ = −α·τ_norm + β·S.
   - `__init__(dt_seconds, tau_clamp=10.0, eps=0.25)`
   - `a = zeros(1)` → **α = softplus(0) = 0.69315 at init**
   - `beta = zeros(1)` → **β = 0 at init**
   - `e = inverse_softplus(0.25)` = −1.25869 → **ε = 0.25 m at init**
   - τ_norm = (τ/dt).clamp(max=10)
   - `head = eta[:,None,:] - barrier` (source = column); S = sigmoid(head/ε),
     or hard threshold with `hard=True`
   - **Docstring states β > 0 rewards open pairs.**
   - Verified: blocked pair attention 0.0739→0.0111 (−85%), rows still sum to 1.

### The variant switch (`make_physics`) [verified at 10918bf]
- `1` → `tau_bias=None`, plain transformer.
- `4a` → PhysicsBias, **β frozen: `requires_grad_(False)` at 0**. Trainable `['a','e']`.
- `4b` → full Φ. Trainable `['a','beta','e']`.

## 6 — The eval design

**Why two models.** The first eval gave 96.1% skill on days 9–10. Investigation
showed days 9–10 are near-static. Both model and persistence "win" by predicting
~nothing. The eval SCRIPT was correct; the test WINDOW had no signal.

- **Benchmark model:** train days 1–8 (`--train-stop 2304`), test frames
  2304–2880. Comparable to FloodCastBench's own split.
- **Stress model:** train days 1–6+8–10 (`--train-stop 2880 --exclude-day 7`),
  test frames 1728–2016. Exercises the mechanism on real dynamics.
- Day 7 can't be both held-out AND in the benchmark training set, hence two models.

**The leak guard (`FloodPairs` exclude):** a training pair at frame i uses
depth[i−24], depth[i], depth[i+24]. None may land in the excluded window. Guard is
`(i + frame_step < ex0) or (i - frame_step >= ex1)` — **strict `<` on the lower
bound** (an off-by-one with `<=` leaked frame 1704 into day 7). Re-verified clean
for the day-7 window on 23 Aug: **0 training frames touch day 7**.

## 7 — Every test run, in order, with the reason for it

### 7.1 Smoke test — unseeded variant 1, both splits
**Why:** prove the pipeline runs end to end and the model isn't lazy.
**Result:** benchmark skill 96.1%, stress skill 96.5%. `diagnose.py` on the stress
model: active-cell skill 95.6%, skill vs zero 36.7%, correlation r=0.7299,
prediction scale 0.78× truth.
**Read:** a real, non-trivial model. Correlation 0.73 was identified as the
headroom the physics should attack.
**Status:** superseded — these runs had no seed and cannot enter the paired table.
Kept as a sanity reference only.

### 7.2 Seeding audit
**Why:** with variant 1 at 96.5%, variant differences would be third-decimal, and
one run per configuration cannot separate signal from run-to-run noise.
**Found:** `train.py` set **no seed at all**.
**Design agreed:** PAIRED seeds — seed *s* runs {1,4a,4b} with the same init and
the same data order, so a 4b−4a gap means physics and not a different shuffle.
3 seeds × 3 variants × 2 splits = 18 runs.
**Implementation:** `--seed` flag; a **private `torch.Generator`** passed to the
DataLoader (a global-RNG-only fix would still give the variants different data
orders, because 4a/4b construct extra parameters before the shuffle begins);
`torch.manual_seed` + `np.random.seed` immediately before model construction;
seed printed in the header; `_s{seed}` added to checkpoint filenames so one seed
cannot overwrite another.
**Verified working:** v1 and v4a printed identical loss to five decimals at s50
(0.04179) and s100 (0.02158). Seed 1 starts at 0.04465 — a different point.

### 7.3 Repo hygiene
**Why:** the checkpoint git-hash tag is worthless if the code that made it isn't
in that commit.
**Found:** ~10 GB of untracked `.pt` files in `git status`; `diagnose.py`
uncommitted; `checkpoints/` and `logs/` not ignored.
**Fixed:** `.gitignore` += `checkpoints/`, `logs/`. Commit **`1b9d00b`**.

### 7.4 Seed-0 benchmark triple at `1b9d00b` — WEIGHT DECAY BUG
**Why:** first replicate of the real ablation.
**Fitted parameters:**
```
4a: alpha=0.70052  beta=0.00000  eps=0.33252
4b: alpha=0.69491  beta=-0.08293 eps=0.31981
```
**The catch:** ε moved in 4a — but in 4a, β is frozen at 0, so ε has **zero
gradient and cannot learn**. The movement had to come from somewhere else.
**Diagnosis:** `AdamW` was constructed with no `weight_decay`, so it used
PyTorch's default **0.01** and decayed the physics parameters.
**Arithmetic check [verified]:** e init = −1.25869; decayed over 101,520 steps at
(1 − lr·wd) predicts **−0.92822**; observed **−0.93018**, difference 0.00196.
4b's e sits 0.048 from pure decay because there β ≠ 0 gives a real gradient.
**Why it mattered:** decay pulls `a` toward 0, and a=0 is exactly α=0.69315. The
regulariser was pinning the travel-time strength at its init and fighting any
gradient — suppressing the paper's central claim. β at −0.083 moved *against* the
decay, so it was the only physics parameter genuinely learning.
**Mechanism note for methods:** AdamW skips parameters whose grad is `None`
(frozen β, hence exactly 0.00000) but still decays parameters whose grad is
exactly zero (ε in 4a). A zero gradient is not a missing one.
**Fix:** optimiser split into parameter groups — transformer weights keep
weight decay (new `--wd`, default 0.01), physics parameters get `weight_decay=0.0`.
Commit **`10918bf`**. Buggy `_best` checkpoints preserved at
`checkpoints/wd_bug_seed0/`.

### 7.9 Two findings that hold across all four physics runs
1. **α never moves.** Init 0.69315 → 0.69509, 0.69660, 0.69023, 0.68998. All
   within 0.5%, and it moves *up* on one split and *down* on the other. The claim
   "the model learns how strongly to weight travel time" **cannot be made**.
2. **β is not stable in sign.** +0.04219 on benchmark, −0.12920 on stress — same
   seed, same code, weight decay already fixed. Either noise, or the gate is
   being used for something other than barrier physics.
